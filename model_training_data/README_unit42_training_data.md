# Unit42 Playbook-Derived Training Data

This folder contains ATT&CK technique sequences extracted from Palo Alto Networks Unit42 **ATOM (Actionable Threat Objects and Mitigations)** playbooks. The data is used to train the sequence-prediction component of the attack-chain forecaster.

---

## 📁 Contents

| File | Description |
|------|-------------|
| `parse_unit42.py` | Extraction pipeline. Parses Unit42 STIX 2.0 bundles and generates ordered technique sequences + supervised training examples. |
| `unit42_sequences.json` | **147 campaign-level technique chains** extracted from 85 Unit42 playbooks. Each entry is a full ordered sequence per campaign. |
| `unit42_training.json` | **1,743 supervised (prefix → target) examples** generated by sliding-window decomposition of the sequences above. Ready for model training. |

---

## 🎯 Purpose

The core problem this dataset solves:

> **STIX relationships tell you which techniques are related. Ordered attack data teaches the model what tends to happen next.**

Unit42 playbooks contain `campaign` → `attack-pattern` relationships grouped by real-world intrusion reporting. By imposing the canonical ATT&CK tactic order on each campaign's technique set, we derive **coarse-grained directional sequences** that serve as training signal for next-step prediction.

---

## 🏗️ How the sequences were generated

### 1. Source
- **Repository:** `pan-unit42/playbook_viewer`
- **Format:** STIX 2.0 bundles (`playbook_json/*.json`)
- **Count:** 85 playbook files

### 2. Extraction logic (`parse_unit42.py`)

```
For each STIX bundle:
  1. Index all objects by ID
  2. Extract attack-patterns → ATT&CK Technique IDs (e.g., T1566)
  3. Read kill_chain_phases → map to canonical tactic order
  4. Follow relationship edges (campaign --uses--> attack-pattern)
  5. Group all techniques under their parent campaign
  6. Sort techniques by tactic order (Recon → Resource-Dev → Initial-Access → ... → Impact)
  7. Deduplicate while preserving first occurrence
  8. Discard campaigns with fewer than 3 techniques
```

### 3. Canonical tactic ordering

The sort key follows the MITRE ATT&CK Enterprise matrix:

```
1.  Reconnaissance
2.  Resource-Development
3.  Initial-Access
4.  Execution
5.  Persistence
6.  Privilege-Escalation
7.  Defense-Evasion
8.  Credential-Access
9.  Discovery
10. Lateral-Movement
11. Collection
12. Command-and-Control
13. Exfiltration
14. Impact
```

### 4. Training example generation

Each campaign sequence of length *N* is decomposed into *N-1* supervised examples using a sliding window:

| Sequence | Generated Examples |
|----------|-------------------|
| `[T1566, T1059, T1083, T1049]` | `([T1566] → T1059)`, `([T1566, T1059] → T1083)`, `([T1566, T1059, T1083] → T1049)` |

## ⚠️ Known limitations

1. **Tactic-ordered, not chronologically ordered.**  
   Unit42 playbooks do not contain timestamps. The order is derived from the canonical ATT&CK tactic sequence. Two techniques within the same tactic phase may appear in an arbitrary order.

2. **Coarse granularity.**  
   This data teaches broad phase-to-phase transitions (e.g., Initial-Access → Execution) well, but fine-grained intra-tactic ordering (e.g., `T1083` before `T1016` within Discovery) is unreliable.

3. **Reporting bias.**  
   Playbooks reflect publicly documented campaigns. Well-studied APTs and ransomware groups are over-represented; stealthy or novel TTPs may be absent.

4. **Not a replacement for true execution traces.**  
   For highest-fidelity sequences, supplement this dataset with:
   - MITRE Attack Flow corpus (explicit step-by-step flow edges)
   - Atomic Red Team / CALDERA lab executions
   - DFIR report timelines with explicit temporal reconstruction

## 🔧 How to use

### Reproduce from scratch
```bash
# 1. Clone the Unit42 viewer repository
git clone https://github.com/pan-unit42/playbook_viewer.git
cd playbook_viewer

# 2. Run the parser on the playbook_json/ directory
python parse_unit42.py playbook_json \
    --output-sequences unit42_sequences.json \
    --output-training unit42_training.json
```

### Load for model training
```python
import json

with open("unit42_training.json", "r") as f:
    training_data = json.load(f)

# Each entry: {"input": [...], "target": "Txxxx", "input_str": "..."}
X = [ex["input"] for ex in training_data]   # prefix histories
y = [ex["target"] for ex in training_data]  # next technique labels
```

### Load for inspection / analysis
```python
with open("unit42_sequences.json", "r") as f:
    sequences = json.load(f)

# Each entry: {"campaign": "...", "sequence": [...], "length": N}
for seq in sequences:
    print(seq["campaign"], "→", " → ".join(seq["sequence"]))
```

## 🧠 Integration with the hybrid pipeline

This dataset feeds the **sequence-prediction model** (LSTM / Markov), while your existing STIX-derived relationship graph feeds the **candidate generator**.

Recommended architecture:

```
STIX Knowledge Graph          Unit42 Sequence Model
       │                              │
       ▼                              ▼
  Candidate pool              Likelihood scores
  (related techniques)        (P(next | history))
       │                              │
       └──────────┬───────────────────┘
                  ▼
           Intersection / Re-ranking
                  │
                  ▼
           Final ranked predictions
```
